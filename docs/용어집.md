# 용어집

이 저장소의 문서와 코드, 에이전트 안내에서 쓰는 말입니다. 분야별로 묶었습니다. 정의 뒤의 괄호는 자세한 곳입니다.

## 입력과 산출물

| 용어 | 뜻 |
| --- | --- |
| SPEC | 블록의 요구사항 문서. 10개 섹션 템플릿을 따르고, 2~4절 표에서 Block Top L1을 만든다 ([SPEC 작성 템플릿](./SPEC%20작성%20템플릿.md)) |
| SPEC 고정 | 승인자가 SPEC 한 판을 실행 입력으로 확정하는 것. 실행은 고정된 판으로만 낸다 |
| 요구사항 ID | SPEC 문장마다 붙는 이름 (`FR-DATA-01`, `TR-01`, `EX-03`, `CRC-E01`). 테스트, 불일치 리포트, 환류, 승인이 이 ID로 이어진다 |
| 의무 수준 | 요구사항의 (필수), (권장), (허용). 정하지 않는 동작은 "미정의" |
| 미정의 | SPEC이 일부러 정하지 않은 동작. Verifier는 검사하지 않고, 최종 승인의 검토 항목이 된다 |
| 열린 질문 | SPEC 10절. 작성자가 답하지 못한 것. 검토 항목이 된다 |
| 구현에 따름(검증하지 않음) | SPEC이 범위만 정하고 정확한 값은 구현에 맡긴 것. 두 클럭의 위상에 따라 달라지는 사이클 수가 대표적이다. Verifier는 정확한 값으로 검사하지 않는다 |
| 사용 조건 | 블록이 동작을 보장하는 입력 조건. 예: 다중 클럭 블록은 "모든 리셋을 함께, 가장 느린 클럭 N사이클 이상 건다" |
| IR | 설계의 중간 표현. 모듈 하나가 JSON 파일 하나이고, 구조는 JSON 필드, 동작은 조각이다 (`schema/ir.schema.json`) |
| L0, L1, L2, L3 | IR의 계층. L0 인스턴스와 연결(Architect), L1 모듈 이름·파라미터·도메인·포트(Architect가 동결), L2 타입과 내부 신호(Author), L3 블록·function·SVA(Author) |
| 조각 | IR 블록의 `body`나 FSM 전이의 `cond`처럼 동작을 적는 자리에 들어가는 코드. SV(기본) 또는 Python 문법(`lang: "py"`) |
| Python 조각 | Python 문법으로 쓴 조각. 읽을 때 SV 조각으로 낮추므로 검사와 방출은 같은 경로를 탄다 |
| 동결 | L1과 인스턴스 목록, `top`/`block_top` 연결을 Author와 Repair가 바꾸지 못하게 고정한 것 (V11) |
| RTL | Emitter가 IR에서 낸 SystemVerilog |
| RTL Freeze | DV와 PI 판정이 모두 pass인 RTL을 승인자가 확정하는 것 |
| 리포트 | 실행 결과 문서. 상태, SPEC 판, 계보, 승인, 판정, 환류 이력 |

## 모듈과 구조

| 용어 | 뜻 |
| --- | --- |
| Block Top | SPEC 하나가 정하는 블록의 최상위 모듈 (role `block_top`) |
| role | 모듈 종류. `top`, `block_top`(인스턴스, 연결, 동기화 셀, `tristate`만), `module`(동작 블록을 가짐), `external`(L1만 있고 등록된 RTL을 그대로 씀) |
| 블록 | 모듈 안의 동작 단위. `comb`, `seq`, `fsm`, `cdc_sync`, `cdc_fifo`, `memory`, `tristate` |
| `comb` | 조합 블록. blocking 대입, 쓰는 신호마다 기본 대입 |
| `seq` | 순차 블록. Emitter가 `always_ff`와 리셋 분기를 씌운다 |
| `fsm` | 상태 기계 블록. 상태 레지스터 `<state_name>_q`를 낸다 |
| `tristate` | `top`/`block_top`의 inout 패드를 구동하는 블록 (push-pull 또는 open-drain) |
| function | 모듈 안의 도움 함수 (IR `functions`). 인자와 지역 변수만 읽고 값을 돌려준다 |
| task | SV의 출력 인자가 있는 서브루틴. 합성 RTL에서 쓰지 않는다 (사내 규칙, V4) |
| SVA | SystemVerilog 속성 (IR `assertions`: assert, assume, cover). 시뮬레이션에서만 돈다 |
| 번들 | 함께 움직이는 포트 묶음 (valid, ready, data). 프로토콜 태그가 붙는다 |
| 프로토콜 태그 | 번들의 규약 이름. 지금은 `valid_ready`(AXI-Stream 포함)만 표준이다 |
| 묶음 워드 | 여러 필드를 한 워드로 이어 붙여 넘기는 포트. 하위 모듈 사이에서는 금지 |
| 모듈 사이 계약 | Architect가 하위 모듈끼리 잇는 연결마다 적는 약속. 실어 나르는 값의 뜻과 사이클 (`contracts.json`) |
| 원시 블록 비중 | 이식 시험에서 IR로 표현하지 못하고 원문에 가깝게 옮긴 부분의 비율 |

## 클럭, 리셋, CDC

| 용어 | 뜻 |
| --- | --- |
| 도메인 | 클럭과 리셋 한 쌍. IR `domains`에 적는다 |
| 클럭 그룹 | 동기화 셀 없이 서로 읽을 수 있는 도메인 묶음. 같은 클럭, 그 분주(`sync_to`), 같은 클럭의 하강 에지 도메인 |
| 하강 에지 도메인 | `edge: neg`. 클럭의 하강 에지에서 도는 도메인 |
| 분주 | `sync_to: {domain, div}`. 같은 원천에서 나눈 클럭 |
| 비동기 포트 | 어느 도메인에도 동기되지 않은 입력 (포트 `domain`이 null). 동기화 셀로만 읽는다 |
| 리셋 방식 | 리셋이 비동기인지 동기인지. 한 설계는 한 방식만 쓴다 |
| 추가 리셋 | `reset.extra`. 주 리셋 다음 우선순위의 동기 리셋 (소프트 리셋). 동기 설계에만 둔다 |
| 리셋 동기화 | `reset.synchronize`. Block Top이 비동기 리셋을 블록 안에서 동기화한다 (`rst_sync` 셀). 비동기 방식으로 센다 |
| 리셋 도메인 교차 | 비동기 리셋으로 바뀌는 레지스터를 리셋이 다른 도메인이 읽는 것. V8 경고 |
| CDC | 클럭 도메인 교차. 다른 클럭 그룹의 값을 읽는 것 |
| 동기화 셀 | CDC용 표준 셀. `cdc_sync`(`2ff`, `gray`, `pulse`)와 `cdc_fifo` |
| 표준 셀 | 파이프라인이 쓰는 검증된 셀 (`pipeline/emitter/stubs/`). 사내 셀을 받기 전까지 임시 표준 |
| 0이 안전한 플래그 | 도메인을 넘는 상태 플래그를 "1이면 진행"으로 정하는 것. 동기화 셀 출력이 리셋 직후 0이라 아직 넘어오지 않은 값이 "멈춤"으로 읽힌다 |

## 파이프라인 단계와 검사

| 용어 | 뜻 |
| --- | --- |
| Validator | 방출 전에 IR을 검사하는 툴. V1~V11 |
| V1~V11 | Validator 단계. V1 스키마와 이름, V2 참조와 도메인 관계, V3 표현식과 폭, V4 조각(읽기·쓰기, 대입 종류, 금지 구문), V5 드라이버, V6 래치와 조합 루프, V7 리셋, V8 도메인, V9 FSM, V10 계층, V11 동결 |
| Emitter | IR에서 RTL을 내는 툴. 구조는 툴이 만들고 조각을 끼운다. 소스맵으로 RTL 줄과 IR 노드를 잇는다 |
| E1, E2, E3 | 방출 뒤 검사. E1 lint, E2 시뮬레이션, E3 SpyGlass (사용자 결정으로 제외) |
| 하니스 | L1에서 툴이 만드는 cocotb 테스트 틀. 클럭, 리셋, 번들 드라이버와 모니터, 프로토콜 체커, 스코어보드 |
| 참조 모델 | Verifier가 쓰는 트랜잭션 수준 기대 모델 (`Model.on_input`) |
| 속성 | Verifier가 사이클마다 검사하는 조건 (`add_property`) |
| T1~T5 | 테스트 검사 종류. T1 초기값 무작위화 시드, T2 프로토콜 체커, T3 참조 모델 비교, T4 속성, T5 커버리지 |
| 후보 | 같은 모듈을 Author 여럿이 따로 쓴 IR. 후보 0은 SV 조각, 후보 1은 Python 조각 |
| 후보 묶음 | 하위 모듈 후보들을 한 Block Top으로 묶어 함께 검증하는 단위 |
| 차분 시뮬레이션 | 같은 무작위 자극을 두 설계에 넣고 출력 트랜잭션 순서를 비교하는 것 (`diffsim`). 후보 사이, 이식 IR과 원본, 재생성과 원본에 쓴다 |
| 번역기 검사 | Python 조각 모듈의 설계 모델과 방출 RTL이 사이클마다 같은지 보는 검사 (`pyequiv`) |
| 설계 모델 실행기 | IR을 Python으로 사이클 단위 실행하는 툴 (`pysim`) |
| 조합 경로 검사 | SPEC 9절이 금지한 입력→출력 조합 경로를 찾는 검사 (`COMB_PATH`, PI는 `eda comb`) |
| 소스맵 | 방출 RTL의 줄과 IR 노드(조각 줄 포함)의 대응. 실패를 노드로 되짚는다 |
| Classifier | 실패를 11가지 유형으로 나누고 Repair, Verifier, 사람, 생성기 버그 중 어디로 보낼지 정하는 툴 |
| 생성기 버그 | 툴(Emitter, 하니스, 셀)의 결함. 골격 lint 오류 등. Repair로 보내지 않는다 (`GENERATOR_BUG`) |
| 검토 항목 | 사람이 최종 승인에서 볼 것. 미정의, 열린 질문, 가정, 경고 |
| 사용량 한도 | 에이전트 런타임의 한도. 걸리면 실행을 실패가 아니라 `paused_quota`로 멈추고 나중에 이어 간다 |
| 예산 | 실행 하나가 쓸 수 있는 에이전트 실행 수 상한 (`budget_agent_runs`) |
| 계보 | 같은 Block Top의 실행 이력 묶음. 환류로 다시 돈 실행이 원래 실행에 이어진다 |

## 에이전트 역할

| 용어 | 뜻 |
| --- | --- |
| 에이전트 | 스케줄러가 작업마다 띄우는 headless coding agent 세션. 격리된 작업 디렉터리에서 정한 출력 파일만 쓴다 |
| Architect | SPEC으로 모듈 트리, 하위 L1, 연결, 계약, 가정을 정한다 |
| Author | 동결된 L1에 L2, L3를 쓴다 (모듈 IR) |
| Verifier | SPEC과 L1만 보고 참조 모델, 속성, 테스트를 쓴다. RTL을 보지 않는다 |
| Repair | 실패한 모듈의 IR을 patch로 고친다. 원인이 형제 모듈이면 그 모듈을 지목한다 |
| Arbiter | 테스트와 RTL이 다를 때 SPEC으로 누가 틀렸는지 판정한다 (`test_wrong`, `rtl_wrong`, `spec_ambiguous`). R6에서는 `spec_gap`, `regen_defect` |
| Porter | 원본 RTL을 이식 IR로 옮긴다 (R3) |
| SpecWriter | 원본 RTL과 이식 IR에서 SPEC을 쓰고, R6 판정에 따라 고친다 (R5) |
| 기댓값 수정 | Arbiter가 `test_wrong`이라 판정한 테스트를 사람이 승인해 Verifier가 고치는 것 |
| Repair 충돌 | 형제 모듈의 Repair들이 원인을 서로 넘기는 것. Design-lead가 고칠 모듈을 지정하거나 Architect 재구성을 요청한다 |
| 가정 | Architect가 SPEC에 없는 것을 정한 기록. L1, 타이밍, 리셋, SPEC 공백에 닿는 것은 검토 항목이 된다 |
| MODEL_FAMILY | Author와 Verifier가 같은 계열 모델일 때의 경고 |

## 원본 RTL 이식 흐름 (P11)

| 용어 | 뜻 |
| --- | --- |
| 이식 흐름 | 검증된 원본 RTL에서 IR과 SPEC을 함께 만드는 흐름. R1~R6 |
| R1~R6 | R1 구조 추출(결정론), R2 사람 답(주파수, 번들, 검토 항목), R3 Porter, R4 원본과 사이클 비교, R5 SpecWriter, R6 SPEC 충실도 |
| 고정 설정 | 이식할 때 정하는 원본의 파라미터 값과 define. 원본의 `generate`는 이 값으로 펼친다 |
| 지운 파라미터 | 고른 구조에서 쓰이지 않아 R1이 IR에서 뺀 파라미터. 원본을 빌드할 때는 그 고정 값을 그대로 준다 |
| 이식 IR | 원본과 모듈 구조가 1:1인 IR. 묶음의 정본 |
| 재생성 IR | SPEC만으로 일반 파이프라인을 돌려 다시 만든 IR. SPEC 충실도 판정에만 쓴다 |
| `reset_only` | R4 결과. 리셋 구간과 직후 몇 사이클에서만 원본과 다르다 |
| `spec_gap` | R6 판정. SPEC이 원본 동작을 정하지 않았거나 두 가지로 읽힌다. SPEC을 고친다 |
| `regen_defect` | R6 판정. SPEC은 분명한데 재생성 설계가 어겼다. 일반 파이프라인 결함으로 리포트한다 |
| 함께 리셋 | R6 비교에서 리셋 도메인이 둘 이상이면 모든 도메인에 같은 시각 구간으로 리셋을 거는 것 (`joint_reset`). 마지막 리셋 뒤 출력만 비교한다 |
| refsim | SpecWriter의 도구. 정한 자극을 원본 RTL에 넣고 출력 트랜잭션과 단독 출력 값을 본다 |
| porteq | Porter의 도구. 이식 IR과 원본을 R4와 같은 방법으로 비교한다 |
| 원본 묶음 | 에이전트 작업 디렉터리에 두는 원본 파일과 R1 요약 (`ref/`) |
| golden 블록 | 손으로 옮긴 IR과 원본 테스트벤치가 있는 공개 블록 (`axis_adapter`, `axis_async_fifo`, `axis_cobs_decode`, `uart`) |

## 부서와 운영

| 용어 | 뜻 |
| --- | --- |
| 부서 | 사람과 장기 에이전트 세션(Seat)이 일하는 조직. 총괄과 Design, DV, PI 세 Pod |
| Pod | 부서의 팀. Design(설계), DV(검증), PI(물리 구현) |
| Seat | OpenRig가 관리하는 장기 coding agent 세션. 부서의 자리 하나 (15개) |
| OpenRig | Seat의 세션, 토폴로지, 메시지를 관리하는 로컬 데몬 |
| Design-lead | 수정 요구의 단일 창구. 환류를 분류하고 Repair 충돌을 결정한다 |
| 환류 | 다른 Pod에서 나온 수정 요구가 파이프라인에 들어가는 형태 (SPEC 변경, 기댓값 변경 등 네 가지) |
| 승인 | 승인자 역할의 사람만 하는 결정. SPEC 고정, 최종 승인, RTL Freeze, 기댓값 변경, SPEC 변경 요청 |
| 게이트웨이 | 사람 인터페이스(Web UI)와 권한, 승인 기록을 맡는 서버 |
| Sanity | 사내 검사 도구 묶음(lint, Xprop, DFT, DCLint 등)과의 연동. 대기 항목 |
| DV | Design Verification. 독립 테스트벤치와 SVA로 RTL을 검증한다 |
| PI | Physical Implementation. 합성, STA, LEC, SDC, 전력 |
| LEC | 논리 등가 검사. RTL과 합성 넷리스트가 같은지 |
| SDC | 타이밍 제약 파일 |
| UPF | 전력 의도 형식. 전력 도메인 출력은 대기 항목 |

## 하지 말아야 할 것과 헷갈리는 말

| 말 | 이 저장소에서 |
| --- | --- |
| "리셋 중" | 동기 리셋이면 리셋을 본 다음 클럭부터 출력이 바뀐다. "rst=1인 동안"만 쓰면 리셋이 걸린 그 사이클을 요구하는 것으로 읽힌다 (SPEC 검사 `RESET_SAME_CYCLE`) |
| "사이클 N" | 리셋이 풀린 첫 사이클을 0으로, 도메인마다 자기 클럭으로 센다 |
| "통과" | 실행 상태 `pass`. 이식 흐름에서는 R6까지 끝난 것. 원본 테스트벤치 통과와 다르다 |
| "IR" vs "RTL" | 에이전트가 쓰고 고치는 것은 IR이다. RTL은 늘 Emitter가 낸다 |
