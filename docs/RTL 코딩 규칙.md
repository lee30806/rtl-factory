# RTL 코딩 규칙

파이프라인이 만드는 RTL이 지키는 규칙입니다. 사람이 손으로 고치는 규칙이 아니라 IR 단계에서 막는 규칙입니다. 에이전트는 SV를 직접 쓰지 않고 IR(JSON 구조와 동작 조각)을 쓰며, Emitter가 RTL을 냅니다. 그래서 규칙은 셋 중 한 곳에서 지켜집니다.

- **Emitter가 만듦**: 구조(포트, `always_ff`, 리셋 분기, 동기화 셀)는 툴이 내므로 LLM이 틀릴 수 없습니다.
- **Validator가 막음**: 조각(동작)에 대한 규칙은 방출 전 V1~V11에서 오류로 돌려줍니다. 오류에는 노드 이름이 붙고 Author나 Repair가 고칩니다.
- **방출 뒤 검사**: lint(E1), 시뮬레이션(E2), 조합 경로 검사가 나머지를 잡습니다.

용어는 [용어집](./용어집.md)을 봅니다. 에이전트가 읽는 작성 안내는 `pipeline/agents/prompts/ir_guide.md`이고, 이 문서와 같은 규칙을 IR 필드 기준으로 적었습니다. 사내 코딩 가이드를 받으면 이 문서와 대조해 빠진 규칙을 Validator에 더합니다.

## 1. 금지 구문

| 규칙 | 강제 | 근거 |
| --- | --- | --- |
| `task`를 쓰지 않는다. 출력이 여럿인 계산은 `comb` 블록에 풀어 쓰거나 function 여럿으로 나눈다 | V4 | 사내 규칙 (2026-10-22). 합성 도구마다 처리가 다르고 읽기 어려움 |
| PLI, VPI, DPI와 시스템 task(`$display`, `$write`, `$finish`, `$stop`, `$random`, `$urandom`, `$time`, `$fopen`, `$readmem*` 등)를 쓰지 않는다 | V4 | 합성되지 않음 (사내 규칙, 2026-10-22) |
| 쓸 수 있는 시스템 함수는 상수 함수와 형 변환뿐: `$clog2`, `$bits`, `$signed`, `$unsigned`, `$countones`, `$onehot`, `$onehot0`, `$size`, `$high`, `$low`, `$left`, `$right` | V4 | 합성 가능 |
| 지연(`#`), `force`/`release`, procedural `assign`/`deassign`을 쓰지 않는다 | V4 | 합성되지 않음 |
| function 본문에 타이밍 제어(`@`, `#`, `wait`)와 재귀를 쓰지 않는다 | V4 | 합성되지 않음 |
| `initial`을 쓰지 않는다. 초기값은 리셋값으로만 준다 | 구조 (조각은 `always` 블록 안의 문장이라 `initial`을 쓸 자리가 없음) | 합성 RTL은 초기값에 기대지 않음 |
| `generate`를 쓰지 않는다. 반복은 `comb`의 `for`, 구조를 바꾸는 설정은 설정마다 IR을 따로 둔다 | 스키마, Emitter | IR이 한 구조만 표현. 원본의 generate는 이식할 때 고정 파라미터로 펼침 |
| 의도적 래치, 클럭 게이팅, 생성 클럭을 쓰지 않는다 | V6(래치), 구조(클럭은 `domains`의 포트에서만 오고 조각은 클럭을 읽지 않음) | v1 범위 밖 |

SVA(`assertions`)는 이 절의 대상이 아닙니다. Emitter가 `` `ifndef SYNTHESIS ``로 감싸고, 실패는 `$display("[SVA] FAIL ...")`로 냅니다.

## 2. 대입과 블록

| 규칙 | 강제 |
| --- | --- |
| `seq` 블록은 non-blocking(`<=`)만, `comb` 블록과 function 본문은 blocking(`=`)만 쓴다 | V4 |
| 블록이 실제로 읽는 신호는 `reads`에, 쓰는 신호는 `writes`에 정확히 적는다 | V4 |
| 신호 하나를 구동하는 곳은 하나다 (블록 하나, 인스턴스 출력 하나, 셀 출력 하나). 입력 포트에는 쓰지 않는다 | V5 |
| `reg`는 같은 도메인의 `seq` 블록 하나만 쓴다. `wire`는 `seq`가 쓰지 않는다 | V5 |
| `comb` 블록은 쓰는 신호마다 본문 첫머리에 조건 없는 기본 대입을 둔다 (래치 금지) | V6 |
| 조합 루프를 만들지 않는다. 인스턴스를 넘는 경로도 자식의 입력→출력 조합 경로로 계산해 본다 | V6 |
| `seq` 블록 안에 임시 변수를 두지 않는다. `comb` 블록의 wire로 뺀다 | 권고 (ir_guide). Validator는 막지 않음 |
| 폭을 맞춘다. 암묵적인 확장과 절단은 오류다. 캐스트(`4'(x)`), 크기를 붙인 상수(`8'd1`), 슬라이스로 명시한다 | V3, lint |
| function은 인자와 지역 변수, 상수만 읽고 쓴다. 모듈 신호는 인자로 넘긴다. 앞에 정의한 function만 부른다 | V4 |
| 클럭은 조각에서 읽지 않는다. sensitivity list를 쓰지 않는다 | Emitter, V8 |

## 3. 리셋

| 규칙 | 강제 | 근거 |
| --- | --- | --- |
| 한 설계의 리셋은 모두 비동기이거나 모두 동기다. 모듈 안의 도메인끼리, `domain_map`으로 잇는 부모와 자식끼리 같아야 한다. 블록 안 리셋 동기화(`reset.synchronize`)는 비동기로 센다 | V2, R1(`mixed_reset` 거부) | 섞인 리셋은 리셋 직후 동작이 두 클럭 위상에 따라 달라짐 (2026-10-21) |
| 표준 셀(동기화 셀, 비동기 FIFO)의 리셋도 설계의 방식을 따른다 | Emitter (`ASYNC_RST`) | |
| 추가 리셋(`reset.extra`, 소프트 리셋)은 동기 리셋 설계에만 둔다. 비동기 설계의 소프트 리셋은 `seq` 본문의 조건으로 쓴다 | 스키마 | |
| 리셋 분기는 Emitter가 씌운다. 조각에 리셋 분기를 쓰지 않는다. 리셋 포트는 `comb` 블록만 읽는다 (예: 리셋 중 ready를 0으로) | Emitter, V8 | |
| 한 `seq` 블록이 쓰는 레지스터는 모두 리셋이 있거나 모두 없다 | V7 | |
| 리셋 없는 도메인에는 `fsm`을 두지 않고 레지스터에 리셋값을 주지 않는다 | V7 | |
| 같은 클럭 그룹에서 비동기 리셋으로 바뀌는 레지스터를 다른 리셋 도메인이 읽으면 경고한다 | V8 (경고) | 리셋 도메인 교차 |

## 4. 클럭 도메인과 CDC

| 규칙 | 강제 | 근거 |
| --- | --- | --- |
| 블록은 같은 클럭 그룹(같은 클럭, 분주, 같은 클럭의 하강 에지)의 신호만 읽는다. 다른 클럭 그룹의 값은 동기화 셀의 출력으로만 읽는다 | V8 | |
| 1비트 수준 신호는 `cdc_sync` `2ff`, 여러 비트 값은 gray 코드로 만든 뒤 `gray`, 1사이클 펄스는 `pulse`(간격은 느린 쪽 3주기 이상), 여러 비트를 흐름으로 넘길 때는 `cdc_fifo` | V2, V8 | 표준 셀만 씀 |
| 비동기 입력 포트는 `cdc_sync`의 `src`로만 읽는다 | V8 | |
| 도메인을 넘는 상태 플래그는 0이 안전한 뜻으로 정한다 ("상대가 준비됨", 1이면 진행). 동기화 셀 출력은 리셋 직후 0이다 | ir_guide, Architect 규칙 | P8a async_fifo: 리셋 중 플래그의 초기 0을 "깨어남"으로 읽음 |
| 하강 에지 도메인은 분주 관계, 동기화 셀, `reset.synchronize`에 쓰지 않는다. 같은 클럭의 상승 에지 도메인과는 `sync_to`(`div: 1`)로 묶는다 | V2 | 표준 셀은 상승 에지 |
| 분주 클럭은 기준 도메인에서 바로 나눈다 (분주의 분주 금지) | V2 | |
| 연결 양쪽의 클럭이 다르면 동기화 셀을 거치거나 받는 쪽이 비동기 포트여야 한다 | V10 | |

## 5. 계층과 연결

| 규칙 | 강제 | 근거 |
| --- | --- | --- |
| `top`과 `block_top`은 인스턴스, 연결, 동기화 셀, `tristate`만 가진다 (동작 블록 없음) | V10 | |
| 인스턴스 입력은 정확히 한 번 연결한다. 번들끼리 잇는 연결은 프로토콜과 역할이 맞아야 한다 | V10 | |
| 클럭과 리셋은 `domain_map`으로만 잇는다 (수동 배선 없음) | V2, Emitter | |
| 하위 모듈 사이에서 여러 필드를 한 워드로 묶어 넘기지 않는다. 필드마다 포트를 둔다 | Architect 게이트 | P8a async_fifo: 묶는 쪽과 푸는 쪽이 비트 순서를 따로 정함 |
| 하위 모듈끼리 잇는 연결마다 계약(실어 나르는 값의 뜻, 몇 사이클 뒤인지, ready의 조합 경로)을 적는다 | Architect 게이트 (`contracts.json`) | P11 cobs: 모듈 사이 1사이클 어긋남 |
| inout은 `top`/`block_top` 경계에서만 `tristate` 블록 하나로 다룬다. 하위 모듈은 `_o`, `_oe`, `_i` 포트로 나눈다 | V2 | 하위 모듈 사이 3상태 버스 금지 |
| 동결된 범위(L1, 인스턴스 목록, `top`/`block_top` 연결)는 Author와 Repair가 바꾸지 않는다 | V11 | |

## 6. FSM, 메모리, 파라미터

| 규칙 | 강제 |
| --- | --- |
| FSM 상태는 enum이다. 리셋 상태에서 모든 상태에 닿을 수 있어야 한다. 나가는 전이가 없는 상태는 경고 | V9 |
| FSM 출력은 `<state_name>_q`를 읽는 `comb`/`seq` 블록이 만든다 | 스키마 |
| 메모리는 쓰기 포트 도메인의 `seq` 블록만 쓰고, 읽기 포트 도메인의 `seq` 블록만 읽는다. `impl: "macro"`는 사내 래퍼 규약을 받기 전까지 방출하지 않는다 | V5, V8, Emitter |
| 다른 파라미터에서 계산되는 값은 `local: true`(localparam)로 둔다 | 스키마, V2 |
| 이름은 SV 식별자 규칙을 따르고 SV 예약어를 쓰지 않는다. 모듈 안에서 이름이 겹치지 않는다 | V1 |

## 7. 방출 뒤 검사

| 검사 | 걸리면 |
| --- | --- |
| E1 lint (Verilator): 조각 안의 경고 | 그 조각의 Repair |
| E1 lint: 골격(조각 밖)의 오류, `UNDRIVEN`, `MULTIDRIVEN` | 생성기 버그(`GENERATOR_BUG`)로 멈춤. Repair로 보내지 않음 |
| SPEC 9절이 출력 레지스터나 조합 통과 금지를 정했는데 입력→출력 조합 경로가 있음 | 검토 항목 `COMB_PATH` (IR 그래프). PI는 합성 넷리스트로 `eda comb` |
| 합성 넷리스트의 조합 루프 | `eda comb` 오류 |
| E2 시뮬레이션의 SVA 실패 | assert는 Repair, assume은 Verifier의 테스트 입력 문제 |

## 8. SPEC에 쓰는 구현 제약

SPEC 9절(구현 제약)에는 이 문서 밖의 블록별 구조만 적습니다. 예: 출력을 플립플롭에서 낸다, 단일 클럭 도메인으로 구현한다, 어떤 표준 셀을 쓴다. 이 문서의 규칙(task, PLI 금지 등)은 Validator가 늘 막으므로 SPEC에 다시 적지 않아도 됩니다. SPEC 문장 규칙은 [SPEC 작성 템플릿](./SPEC%20작성%20템플릿.md)에 있습니다.
